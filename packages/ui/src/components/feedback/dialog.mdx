# Dialog

A modal window: a sheet that slides up from the bottom on mobile, a centered window from 768px.

## When to use it

- To confirm an important or irreversible action, especially sending units, with a summary including the amounts.
- For a short form related to the current screen.
- Not for long content: open a page.

## What the consumer provides

- `title`: the question, which repeats the action ("Send 20 units to Lucas Petit?").
- `description`: the concrete consequences (new balance).
- `actions`: main action, then secondary. On mobile they stack full width, the main one on top; on desktop they align right, the main one on the right.
- `children`: optional content between the description and the actions, such as a short form.
- `open` + `onClose`: close button, click on the scrim, Escape key.
- `closeLabel`: accessible name of the close button ("Close").
- `alert`: `role="alertdialog"` for a destructive confirmation; a click on the scrim does not close it, the member has to choose.
- `finalFocus`: the element that gets the focus on close, when it is not the button that opened the dialog.

On open, focus goes to the first interactive element and stays trapped in the window; on close, it returns to the button that opened it (Ark UI's `Dialog`). The close button comes last in the document, although it is shown at the top right, so that the focus goes to the content first. An `alert` dialog focuses the close button instead, so that Enter does not confirm a destructive action by accident.

The window is `bg-surface-raised` with `shadow-lg` over a `bg-overlay` scrim: at the bottom with `radius-xl` top corners on mobile, above the phone's home indicator; centered, 480px wide at most, with `radius-xl` corners from `md`.
