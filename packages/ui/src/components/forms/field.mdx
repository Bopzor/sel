# Field

The label, the hint and the error around a form control, stacked: the label and the hint above, the error below.

## When to use it

Around every control of a form that has no label of its own, such as an `Input`. The application's form components (bound to its form library) wrap their control in a `FormField`.

## What the consumer provides

- `label`: required and visible. The placeholder never replaces the label.
- `hint`: help shown under the label, before the control, so that it is read before typing.
- `error`: a message that says what to do ("The end of the address is missing, for example marie.dupont@example.com"), never just "Invalid format". Shown with an icon, linked to the control with `aria-errormessage` and announced when it appears.
- `disabled`, `required`: passed to the control.
- `children`: a single control.

## Parts

`FormField` is a shortcut for the common case. When the label needs more than text (an "Optional" mark, a link next to it) or the parts go in another order (a counter under the control), the field is written with its parts:

```tsx
<Field.Root invalid={Boolean(error)} required>
  <Field.Header>
    <Field.Label>Label</Field.Label>
    <Field.Hint>Hint</Field.Hint>
  </Field.Header>
  <Input />
  <Field.Error>{error}</Field.Error>
</Field.Root>
```

- `Field.Root` (required): `invalid`, `disabled` and `required`, passed to the control.
- `Field.Label` (required): the label.
- `Field.Header`: groups the label and the hint, closer to each other than to the control.
- `Field.Hint`: the hint.
- `Field.Error`: the error, only rendered while the field is `invalid`.

## Rules

- Ark's `Field` links the label, the hint and the error to the control, and passes it `disabled`, `required` and the invalid state: these states are set on the `FormField` or the `Field.Root`, not on the control.
- Validate on submit first, then on each change.
