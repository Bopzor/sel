# RichTextEditor

A multi-line input with simple formatting: bold, italic, underline, links and lists. It has no label: put it in a `FormField`, which adds the label, the hint and the error, and gives it its states. It has the same box as `TextArea`, and a formatting toolbar under the text.

## When to use it

For a text that other members read, where a list or a link helps: the message of a request, an event or a piece of information, a comment. For plain text (a profile presentation, a short note), use `TextArea`.

## What the consumer provides

- `value` + `onChange(html)`: the editor is always controlled. The content is HTML, an empty string when the editor is empty. The application sanitizes this HTML before showing it with `RichText`.
- `onBlur` and `ref` (whose `focus()` moves the focus to the text), for a form library: with react-hook-form, the editor goes through a `Controller`.
- `disabled`, `required`, `aria-invalid`, `id`, `aria-label`, `aria-labelledby`, `aria-describedby`: they override the `FormField`'s. Outside a `FormField`, an `aria-label`, like `Input`.
- `placeholder`: an example of content, never a replacement for the label.
- `children`: its `RichTextEditor.Toolbar` (see below).

## Parts

```tsx
<RichTextEditor.Root value={value} onChange={setValue}>
  <RichTextEditor.Toolbar>
    <RichTextEditor.Bold label="Bold" />
    <RichTextEditor.Italic label="Italic" />
    <RichTextEditor.Underline label="Underline" />
    <RichTextEditor.Link labels={linkLabels} />
    <RichTextEditor.BulletList label="Bulleted list" />
    <RichTextEditor.OrderedList label="Numbered list" />
    <RichTextEditor.ToolbarEnd>…</RichTextEditor.ToolbarEnd>
  </RichTextEditor.Toolbar>
</RichTextEditor.Root>
```

- `RichTextEditor.Toolbar`: the bar under the text. The formats offered are the buttons it contains, in that order.
- `RichTextEditor.Bold`, `RichTextEditor.Italic`, `RichTextEditor.Underline`, `RichTextEditor.BulletList`, `RichTextEditor.OrderedList`: a format each, named by `label` in the application's language.
- `RichTextEditor.Link`: the link button and its dialog, with their texts in `labels` (`button`, which is also the dialog's title, `url`, `invalid`, `apply`, `remove`, `cancel`, `close`).
- `RichTextEditor.ToolbarEnd`: actions placed at the end of the toolbar, such as an attachment button or the send button of a comment. The editor only renders them.
- `RichTextEditor.ToolbarButton`: a button with the style of the toolbar, for an action of the application (attaching a file). It is disabled with the editor.

## Rules

- Pasted content keeps paragraphs, bold, italic, underline, links and lists, and loses the rest (headings, colors, tables).
- The link button opens a dialog with the address. An address without a scheme ("example.org") gets `https://`. With no selected text, the address is inserted as the link's text. An unsafe address (`javascript:`) is refused, with the `invalid` error under the field.
- A pasted address becomes a link on its own. A link does not open on click while editing.
- The toolbar buttons show their state with `aria-pressed` and the `bg-primary-subtle` background, like the active entry of a navigation. They keep the focus and the selection in the text when clicked with the mouse.
- The keyboard shortcuts of the formats work too: Ctrl/⌘ + B, I, U, and Ctrl/⌘ + Shift + 7 and 8 for the lists.
- The text is `body`, like `TextArea`. The content is styled by the typography plugin's `prose` class and the `prose-theme` utility, like `RichText`, which shows it without editing: spaced paragraphs, bulleted and numbered lists, `text-primary` underlined links.

## Accessibility

The editable text is a `role="textbox"` with `aria-multiline`, named by the `FormField`'s label, described by its hint and linked to its error with `aria-errormessage`, and marked with `aria-invalid`, `aria-required` and `aria-disabled`. A click on the label moves the focus to the text. When the link dialog closes, the focus goes back to the text.
