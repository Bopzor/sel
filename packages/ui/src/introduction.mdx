# Design system

This design system is the foundation of the application for LETS (Local Exchange Trading Systems), on phones as well as on computers. Every choice goes the same way: a screen must be understood without help, read without effort and touched without aiming. It is built for several instances: each LETS can change its brand and accent colors, its name and its logo without touching anything else.

## Principles

1. **One thing at a time.** A screen answers one question or leads to one main action. Long flows are split into steps (`Stepper`).
2. **Everything is readable.** Body text is 17px (`body`), never less than 14px (`caption`). Contrast is above 4.5:1 everywhere, in both themes.
3. **Everything is touchable.** Every interactive element offers at least 44px (`touch-target`); buttons and fields are 48px (`control-md`). The only exception is the compact `control-sm` size (40px), reserved for administration areas.
4. **Nothing is implicit.** Icons have a label, states never rely on color alone, errors say how to fix them.
5. **You can always go back.** Important actions ask for a confirmation with a summary, reversible actions offer "Undo".

## Using the package

The package is consumed from its sources, like the other workspace packages.

```css
/* The application's stylesheet: Tailwind, the Inter font, the tokens and the base styles. */
@import '@sel/ui/styles.css';
```

```tsx
import { Button } from '@sel/ui';

<Button icon="send">Send</Button>;
```

- Tokens are exposed as Tailwind utilities (`bg-surface`, `text-muted`, `border-strong`, `rounded-md`, `shadow-sm`…). Tailwind's defaults are removed and the linter rejects arbitrary values: only the design system's tokens can be used. See [Tokens](?path=/docs/tokens--docs).
- The dark theme applies under `data-theme="dark"` on `<html>`. The colors are defined with `light-dark()`; Tailwind compiles it into CSS variables that the theme switches, so the theme applies to the whole page and cannot be changed on a nested element.
- Components live in `src/components/`, each with its stories and its guideline (a `.mdx` page). Run `pnpm storybook` in this package to browse them, along with these guidelines. [Contributing](?path=/docs/contributing--docs) sets the conventions for writing one.

## Logo

`src/assets/` holds the application's logo: a rosette of eight dots, each extended by an arc, arranged in a circle.

- `logo.svg`: color version on a white background (`#ffffff`), shown with `radius-md` corners at 44px in `SideNav` and the header, or larger on the home page.
- `logo-monochrome.svg`: a single ink, black (`#000000`) on a transparent background; for favicons and print. Do not place it on a dark background.

An instance can replace this logo with its own (square SVG, readable at 44px): see [Customizing an instance](?path=/docs/guidelines-theming--docs). The rosette's colors belong to the logo and are not tokens.
